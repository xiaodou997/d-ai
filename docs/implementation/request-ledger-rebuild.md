# 请求、用量与资金账本重构验收记录

日期：2026-09-14。代码在 `main` 工作区完成；生产维护按用户要求另行安排，今天未连接、清理或切换生产数据库。

## 实现范围

- 执行事实、用量证据、明确请求错误和资金结算分离。新请求表没有总括性的成功／失败字段；对外记录 DTO 不再输出 `request_status`。
- 明确错误即使带 usage 也保留证据、记录参考成本，两层余额与 Key／订阅金额额度均免收。未报告和明确报告零值分别保留；不根据正文估算 Token。
- 客户端断开立即取消上游，只按取消前已采集的证据结算。终止帧发送前封存必要证据；终态后不再等待 EOF。尚未向客户端提交响应的失败尝试允许按策略重试，尝试证据单独保存，只计最终有效尝试。
- 调用前持久登记身份和价格快照。在途租约丢失后进入中断诊断并免收；晚到的完成不能重新扣费。外部 X-Request-Id 不再作为财务幂等身份，内部异步任务使用受信任身份。
- `bill_settlements` 承担唯一持久消费队列。后台事务按固定顺序锁账户，原子完成余额、Key、订阅、流水和过账标记。调用线程不锁资金账户；过账前费用显示处理中，异步任务的实际扣款字段保持为零，提交后才更新。
- `bill_journal` 追加记账，原用量／价格／应收快照不可修改。充值、额度变动和到期通过数据库触发器进入资金流水。退款追加反向流水，重复退款不重复退钱，过期或已切换订阅窗口不会被重新激活。
- 运行数据库角色不能修改余额或结算处理状态；只允许登记结算及补记不影响金额的交付中断事实。计费角色负责实际账务事务。
- v2 请求、错误和费用查询按主体授权，时间＋ID 游标分页。管理员可查内部尝试，租户和用户只能查看授权范围内的脱敏证据和相关价格。三端主页面及辅助入口已迁移；旧记录查询路由和全局正文记录配置入口已移除。
- 请求与账务月分区、诊断与调试日分区。保留期为 90／30／7／365 天；财务清理先验证余额及额度守恒，再生成结转。未完成任务阻止清理，关闭期间拒绝历史重放。
- 调试默认关闭，按租户／Key／模型限时开启 1–24 小时；独立 gzip 保存，上限 1 MiB，超限标明省略，认证信息和内嵌媒体不保存。
- schema 41 用于离线准备，schema 42 完成旧记录和重复结算表释放。运行程序只接受 schema 42；切换工具核验外部备份、资产快照和所有遗留队列，使用 RESTRICT 删除，未知依赖会阻止操作。

现有跨域报表通过只读 `ai_consumption_projection` 读取同一结算事实，并非第二套持久消费模型。旧执行正文写入器、audit inbox worker、消费 outbox 和旧请求界面组件已移除。

| 切换后 | 3,457,024 |

余额、负债、资金批次及有效期、Key 已用额度、订阅累计与窗口用量和支付／充值身份的快照哈希一致。该数值只证明隔离演练中的空间释放，不能推算生产节省量。

同租户 128 笔消费、16 个并发写入与结算工作器：封存总耗时约 454 ms，封存 p95 约 210 ms，实际扣款阶段约 1.09 s。封存阶段余额不变，最终两层余额及负债守恒。此为本机隔离测试，不作为生产容量承诺。

## 审查修复（2026-09-14）

- 转换器产生的完成帧由执行层暂存，确认上游整体结束并持久封存后才发送；封存失败不再向客户端发送完成事件。
- Chat／Gemini 的候选结束事实跨帧累计，结合请求中的候选数量判定完整性。单个候选结束不能使其余候选截断的请求进入计费。
- 内部 Replay 必须携带数据库保存的任务创建时间，财务准入据此校验关闭账期；本次接收时间只用于运行耗时。历史幂等记录删除后，新接收时间也不能使旧任务重新准入。
- 回归覆盖转换终止帧的封存顺序与故障、多候选缺失／分帧完成、Replay 到执行对象的时间传递、任务重试时间不变及隔离数据库中的历史重放拦截。
