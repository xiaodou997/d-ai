# 上游调度与稳定性

运行时可用性与管理员启停分开。额外模型探测调用为零：冷却到期自动重新参与真实业务选路，恢复期每个故障范围最多一个并发，连续两次成功后恢复正常并发。旧请求通过租约代次和唯一占位被隔离，不会改变新状态。

普通故障连续五次，或六十秒内至少二十个有效样本且失败率达到百分之五十，进入冷却。退避依次为三十秒、一分钟、两分钟、四分钟、五分钟；稳定十分钟且成功十次后清除退避等级。认证拒绝冷却三十分钟。429 遵守 Retry-After，无有效提示时使用普通退避。人工停用和资源授权始终优先。

网络故障作用于端点，认证拒绝作用于账号或单个 OAuth 凭据，模型故障和限流作用于端点/凭据、模型、操作。池内凭据作为独立执行候选，与直连端点统一参与分组策略；旧池级轮询和权重选择退出业务执行路径。最终一次请求成功不会掩盖之前失败的上游尝试。成功率排除用户参数错误、取消、准入跳过和网关本地错误。

配置项 `runtime.upstream_max_attempts` 默认 3，允许 1–8，计数所有真实模型 HTTP 发送。OAuth 刷新后的重发也由执行器控制。已提交响应不重试，图片结果不确定时不自动重复生成。

管理员接口：

- GET `/api/v1/upstream-stability?kind=direct_upstream|oauth_pool&window=1h|24h|7d`
- GET `/api/v1/upstream-stability/{kind}/{id}?window=24h`
- POST `/api/v1/upstream-stability/{kind}/{id}/resume`：立即允许业务试用，不发送探测，不删除历史。

仅平台管理员与超级管理员可调用。账号/池页展示样本数、统计覆盖起点、失败类型、延迟与模型明细；最近一小时三次冷却提示反复异常。租户分组不包含运行熔断字段。

## 维护窗口切换

1. 停止接收新请求，排空所有在途请求，停止旧版本所有网关与后台进程。
2. 备份数据库及 Redis 的 `dai:health:*`、粘性绑定。执行 `internal/db/changes/0043_20260914_upstream_availability.sql`，再按当前部署角色执行 `internal/db/ownership.sql`。
3. 同时更新后端与 Portal。新版本首次启动把旧熔断迁入最多五分钟冷却；旧认证异常迁入三十分钟冷却；保留人工停用。迁移幂等，不清空 Redis。
4. 旧粘性绑定仅在新的候选与层级仍匹配时可使用；不匹配即重新选路。
5. 检查管理员运行状态、错误分类、实际发送次数和 `/api/v1/system/status` 的 `health.state_error`；确认就绪后开放流量。

数据库统计从新版本覆盖起点开始，不补造历史结果；沿用三十天尝试记录保留期。数据库升级不删除旧请求记录。回退必须关闭流量、排空并恢复配套备份，禁止新旧状态协议混跑。

## 本次验收

- 全量 Go 测试在真实 PostgreSQL / Redis 环境运行，包括数据库迁移、计费不变量和请求重复封账；网关候选及真实数据库端点展开另有专项测试。

- Portal 全量测试 137 个文件、411 项通过；类型检查、OpenAPI 契约、权限矩阵、依赖方向、源码及构建样式检查通过。
- 静态 Portal 制品输出到 `release/portal`。迁移仅在隔离测试 schema 演练，部署仍按上述维护窗口流程执行。
