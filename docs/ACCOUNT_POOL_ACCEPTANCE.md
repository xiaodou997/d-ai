# v0.3.26 上游账号与账号池人工验收

验收环境：升级后的生产 Portal；使用专门的测试账号和分组。发布前生产 schema 为 46，OAuth 凭据数为 0。API-key 账号功能可以直接验收；OAuth 用例需要先导入有效测试账号。不要把 token、密钥或包含凭据的网络报文写入验收记录。

## 必验流程

| 优先级 | 操作 | 预期结果 |
|---|---|---|
| P0 | 在上游账号编辑页同时修改 API key、节点地址并保存；重新打开 | 一次保存生效，两处信息一致；保留空白 key 时沿用原 key |
| P0 | 保存账号时让其中一个节点校验失败 | 整次保存失败，账号 key 和其他节点不发生部分更新 |
| P0 | 在账号池导入两个有效测试账号，编辑名称、权重、工作区及 token | 同一窗口保存；不修改 token 时留空，原凭据保留；身份不变的普通编辑不清空工作区 |
| P0 | 重复导入同一账号；批量导入中让一条失败再重试 | 重复项提示冲突；重试只提交失败项，成功项不会重复添加 |
| P0 | 点击“更新上游配额” | 有权限的账号显示上游报告的真实数值和重置时间；部分失败单独提示并保留旧观测；无数据显示未知 |
| P0 | Codex 池点击“识别账号模型”，使用模型权限不同的两个账号 | 分别显示各账号模型；请求只选模型已授权的账号；未知或过期目录不会直接禁用账号 |
| P0 | 配置有效公共模型绑定，分别发送流式和非流式请求 | 流式逐步输出；非流式返回单个 JSON；Codex 非流式响应不包含 SSE `data:` 行 |
| P0 | 调用一个简单工具，随后带工具结果发第二轮请求 | 工具名、参数、调用 ID 和结果对应，第二轮继续成功；Chat、Responses、Messages、Gemini 按实际使用的入口验收 |
| P0 | 检查上述请求的使用记录和扣费 | 使用上游报告的 token；请求状态、账号、模型和尝试次数准确；无重复结算 |
| P1 | 分别选择轮询、权重策略，以新会话连续请求 | 新会话轮换账号；权重策略长期比例符合配置；同一会话按粘性策略保持账号 |
| P1 | 停用池或某个账号，再发送请求 | 停用对象不会被选中；恢复启用后可重新使用 |
| P1 | 使用确实报告耗尽的测试账号或已有异常记录，检查运行状态 | 模型额度耗尽只限制对应模型；共享容量不足显示临时限制，不把账号永久标为认证失效 |
| P1 | 输出后停止生成或关闭连接 | 请求及时结束，不在后台换账号重放；使用记录保留实际用量和取消原因 |
| P1 | 刷新配额或识别模型期间切换池、编辑账号或停用账号 | 迟到的结果不会覆盖新池、恢复旧身份的数据或重新启用账号 |
| P1 | 手机窄屏打开账号池，完成查询和编辑 | 页面没有整体横向溢出，操作按钮可点击，表格内部滚动正常 |

## 查询边界

- 主动查询使用原生账号接口：Codex `wham/usage`、Claude `api/oauth/usage`、Gemini CLI `retrieveUserQuota`、Antigravity `fetchAvailableModels`。接口权限、项目 ID 或上游契约变化可能使查询不可用；这不等于生成请求不可用。
- 活跃账号池每 5 分钟尝试更新配额，最多同时查询 4 个账号；同账号的重复查询合并，手动刷新有短时间节流。普通列表刷新只读已有配额。
- 配额来自上游响应头或配额接口。D-AI 本地计费金额、请求量不用于估算订阅剩余额度。
- Claude 主动查询只将明确的共享窗口用于账号整体限制；不把某个模型家族的限制应用到其他模型。
- 当前只有 Codex 支持主动识别账号模型；其他提供方的目录建议不视为账号权限证明。

## 验收记录

每项记录“通过 / 不通过 / 环境缺失”，并附时间、请求 ID、入口、公共模型和脱敏截图。失败时先看使用记录的尝试链与账号池运行状态；不要只凭首页或容器健康判断业务成功。

发布冒烟检查包含公开 `/health`、Portal、`/api/v1/info`，以及容器内管理 `/ready`、`/metrics`。数据库保持 schema 46；此次不执行迁移。旧镜像和旧二进制保留用于应用回退。
