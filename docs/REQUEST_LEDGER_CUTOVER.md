# 请求与账本切换手册（schema 40 → 42）

本次发布需要停机切换。2026-09-14 用户已明确：**今天不执行生产切换**。此文档和工具用于后续维护窗口；不能将隔离演练结果当成生产空间报告。

## 发布条件

所有业务矩阵、协议、权限、账务并发、退款和迁移测试通过，前后端使用同一版本。生产目标、运行账号、服务停止命令和独立备份目录需要在维护工单中填写。旧版程序只能连接 schema 40，新程序只接受 schema 42；应用不自动执行升级 SQL。

新模型中 `bill_settlements` 是唯一持久消费结算入口。日志清空不恢复余额、Key 额度或订阅权益。保留 `bill_accounts`、`bill_credit_lots`、充值及支付／退款订单、身份、模型、路由、工作台和生成文件。

## 维护前准备

1. 构建后端、前端和 `cmd/record-cutover`，留存旧发布包；不要使用仓库内个人未提交的嵌入页面作为生产包。
2. 将连接配置放在受保护的部署配置中，或通过 `DAI_CUTOVER_DATABASE_URL` 环境变量提供；不要把密码写入操作报告。
3. `record-cutover --action inspect` 只读输出数据库、schema、版本、表／索引／TOAST 占用。归档输出到维护工单。
4. 在独立存储准备足够空间保存完整 PostgreSQL custom-format dump 和 `.manifest.json`。备份文件使用绝对路径；工具拒绝覆盖已有文件。
5. 检查数据库和生成文件所在磁盘容量。媒体资产需保留，不能为了释放空间删除工作台仍引用的生成文件。

## 维护窗口步骤

1. 在入口停止新模型请求，等待或明确取消在途生成、异步任务。停止所有旧网关进程、旧扣款和审计写入器、支付轮询及回调处理进程。上游生成不得在客户端断开后继续排空。
2. 处理旧扣款队列、退款和已支付未入账订单。不能通过直接删除待处理行绕过切换检查。若支付服务继续投递回调，入口应暂存于支付方重试机制，恢复后依赖保留的订单和幂等标识处理。
3. 使用 `record-cutover --action backup --offline --backup /独立存储/本次维护/production.dump` 保存全库备份和资产清单。工具的 `--offline` 是操作者对已停止写入的声明，不能替代实际停止服务。`pause` / `resume` 仅控制新调用准入，不替代停进程；`resume` 只接受已切换的 schema 42。
4. 用数据库所有者执行 `internal/db/changes/0041_20260914_request_ledger_rebuild.sql`。此阶段建立新模型和期初检查点，保留旧历史，且新计费准入关闭。
5. 使用同一备份路径执行 `record-cutover --action verify --offline --backup ...`，核验 dump 哈希及余额／资金到期属性／Key 和订阅权益快照。任何差异必须查明，不能归零处理。
6. `record-cutover --action release --offline --backup ...` 在事务中再次核验资产并释放旧历史表，更新为 schema 42。不要另行重复执行 0042；0042 是等价的数据库管理员手工发布脚本，工具路径优先。未知依赖会阻止删除；禁止改为 `CASCADE`。
7. 按实际部署角色执行 `internal/db/ownership.sql`，用运行和计费账号分别验证权限，执行 schema 检查。保留本次资产哈希、删除清单和释放后的占用报告。
8. 启动新版程序但保持外部流量关闭；在入口隔离条件下执行 `record-cutover --action resume`，仅放行维护验收调用。验证正常结算、流内错误免收、取消只计已报告用量、退款、订阅及 Key 额度和账本守恒。
9. 验收通过后恢复外部流量及支付处理；观察结算积压、明确错误和客户端中断分别计数。结算最老积压超过 30 秒时，新计费调用应返回暂不可用，已有结算继续重试。

`release` 拒绝新账已发生资金变动、未完成结算、活动执行租约、未处理异步任务或支付操作等情形。若任一检查失败，应保持维护并处理原因。

## 回滚边界

在新系统还未产生资金变动时，可停止新版并从备份恢复旧库与旧程序。验收调用一旦产生扣款、退款、充值或其他新资金变动，不能再用旧快照覆盖数据库；必须前向修复并保留新流水。

## 空间报告

报告分别记录：旧表／索引／TOAST 实际大小、数据库大小、数据库所在文件系统可用空间、独立备份大小和位置。DROP TABLE / DROP PARTITION 释放关系文件；不把 PostgreSQL 缓存变化、并行测试产生的数据或外部备份大小混作生产节省空间。

隔离测试 `TestRequestCutoverPreservesAssetsAndReleasesHistory` 使用 schema 40 快照及合成旧正文，核对切换前后资产哈希和负余额。首次演练成功删除约 17 MB 合成历史；该数字仅用于验证释放动作，不能推算生产收益。

## 持续保留策略

请求 90 天，错误及尝试 30 天，调试正文最多 7 天，结算与资金逐笔证据 365 天。以完整分区为清理单位，月分区可能比标称保留期多保留不足一个月。调试默认关闭，按租户／Key／模型限时开启 1–24 小时；不保存认证字段及内嵌媒体，原始正文超过 1 MiB 标明省略。

账务清理先核验期初／结转＋流水＝当前余额及额度，再写结转检查点。未完成结算、待处理冲突和未核验差异阻止清理。诊断删除不影响保留期内费用查询和退款。逐笔账过期后，通过独立带原因的余额调整进行补偿。

对外模型请求仍使用原 `/v1/*` 协议、API Key 和模型配置。财务请求 ID 由服务端生成，并在流式响应开始前写入 `X-Request-Id`；客户端传入的同名头不再决定账务幂等身份。客户端应保存返回的 ID 用于查账与排障。
