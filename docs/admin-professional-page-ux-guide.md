# 通用专业配置页体验优化指南

这份文档用于指导 AI 或开发者优化“专业概念多、参数多、普通用户不容易理解”的后台配置页。它不绑定某个项目、框架或 UI 组件库；如果项目不是 Vue 或 Element Plus，也应按同样的信息结构、文案原则和交互模式迁移到对应技术栈。

本项目中的参考实现：

- `admin/src/views/AIGateway/GatewayRouting.vue`
- `admin/src/views/AIGateway/GatewayLimits.vue`

目标：把专业配置页做成“用户看得懂、敢操作、知道影响、能从预设开始再微调”的工作台，而不是只暴露数据库字段或接口参数。

## 适用范围

适合使用本指南的页面：

- 参数含义专业，例如路由策略、限流策略、计费规则、风控规则、调度权重、模型参数、安全策略。
- 用户需要配置多个相关字段，字段之间存在组合关系或约束。
- 错误配置会带来成本、性能、稳定性、安全性或业务影响。
- 页面里存在缩写、英文术语、内部字段名、算法名或系统状态名。
- 用户经常问“这个页面是干嘛的”、“这个值怎么填”、“调大调小有什么影响”。

不适合过度使用本指南的页面：

- 纯详情页或纯日志页，没有配置行为。
- 只有 1 到 2 个简单字段的表单。
- 面向专家的低层调试工具，用户明确需要原始字段名。
- 已经有成熟设计系统规定了完全不同的信息结构。

## 改造前先弄清楚

开始设计前，先从代码、接口或业务文档中回答这些问题。没有答案时，用页面可见信息做保守推断，并避免编造业务规则。

1. 这个页面最终影响什么？
   例如影响后续请求、只影响新增配置、不影响历史记录、不修改价格、不修改授权关系。

2. 用户在这里要完成什么动作？
   例如新增策略、调整权重、启停规则、选择范围、保存参数。

3. 哪些词是内部术语？
   例如 `scope`、`RPM`、`TPM`、`latency`、`softmax`、`circuit breaker`。

4. 哪些字段有风险？
   例如数值过高会冲垮上游，过低会误伤用户；权重合计必须为 1；留空代表不限制。

5. 有没有常见配置组合？
   如果有，就做成预设按钮；如果没有，就给出“保守默认”、“成本优先”、“性能优先”、“稳定优先”等可解释方案。

6. 系统实际如何处理？
   用 3 到 4 步解释，不要用实现细节堆砌。

## 信息架构标准

专业配置页优先使用下面结构。不同项目可以换组件，但信息顺序应保持一致。

### 1. 主配置卡片

主卡片是页面核心，包含标题、简短解释、主要操作和配置内容。

标题要求：

- 用业务结果命名，不用接口资源名。
- 示例：`限流策略`、`路由策略`、`计费规则`。

副文案要求：

- 一句话说明页面做什么。
- 一句话说明保存后影响范围。
- 避免算法名、缩写、内部字段名。

示例：

```text
设置系统选上游路线时更看重什么：更省钱、更快、更空闲，还是更稳定。
保存后影响后续新请求，不会修改历史调用记录。
```

### 2. 默认折叠的说明区

专业说明应靠近操作区，但默认折叠，避免首屏过长。

放置位置：

- 放在主卡片标题下面。
- 放在统计卡、筛选器、表格或表单上面。

标题写法：

- `限流如何生效`
- `系统会怎么选路`
- `这些参数怎么影响结果`
- `查看匹配顺序和关键术语`

折叠内容建议包含：

- 系统处理流程：3 到 4 步。
- 关键术语解释：每个术语 1 到 2 句话。
- 风险提醒：调高、调低、留空、关闭的后果。

### 3. 当前状态反馈

如果页面管理的是一组策略、规则、配置项，应提供 3 到 4 个状态卡。

状态卡用于帮助用户建立整体感，而不是装饰。

常见统计：

- 启用数量 / 停用数量。
- 覆盖对象数。
- 指定模型数。
- 当前合计 / 是否有效。
- 最近更新时间。
- 当前匹配范围。

### 4. 主操作区

根据页面类型选择：

- 表格型：筛选器 + 表格 + 行内状态 + 编辑入口。
- 表单型：参数组 + 可视化反馈 + 保存按钮。
- 混合型：上方配置，下方说明或历史列表。

要求：

- 表格列名使用用户语言。
- 空值要解释含义，例如“全部模型”、“不限制”，不要只显示空白。
- 状态要用标签，不只显示 `active`、`disabled`。
- 危险动作要可回退或有明显状态反馈。

### 5. 弹窗或抽屉

复杂表单必须分区，不要堆成长表单。

推荐分区：

1. 作用范围：这条配置管谁。
2. 推荐预设：常见配置组合，一键填入。
3. 核心参数：真正需要用户确认的数值。
4. 状态和影响：启用、停用、保存后何时生效。

## 文案设计规则

### 把内部词翻译成用户词

| 内部词或字段 | 推荐页面表达 | 说明 |
| --- | --- | --- |
| Scope | 作用对象 | 表示这条配置管租户、用户、Key、服务等哪个对象 |
| Scope ID | 对象 ID | 避免让用户理解数据库主键含义 |
| RPM | 每分钟请求数 | 首次出现可写“每分钟请求数（RPM）” |
| TPM | 每分钟 Token | 首次出现可写“每分钟 Token（TPM）” |
| concurrency | 同时请求数 | 比“并发”更适合普通用户 |
| latency | 响应速度 | 避免只写“延迟” |
| load / inflight | 繁忙程度 | 说明当前排队或处理中请求多少 |
| health | 可用状态 | 说明是否健康、是否在恢复期 |
| circuit breaker | 保护期 | 比“熔断 OPEN/HALF_OPEN”更易懂 |
| normalize | 按比例修正 | 可在说明里解释“归一化” |
| softmax | 概率选择 | 不必暴露算法名 |
| sticky | 会话保持 | 说明同一会话尽量走同一路线 |

### 每个参数至少说清三件事

对每个核心参数，写清楚：

1. 它是什么。
2. 调大、调小或留空会怎样。
3. 适合什么场景。

示例：

```text
每分钟请求数
一分钟内最多允许多少次请求。适合防止短时间内请求突然打满。留空表示不按请求次数限制。
```

### 避免这类文案

不要写：

```text
配置 scope、capability、model 维度的 runtime limit policy。
```

应该写：

```text
设置谁、调用什么能力、每分钟最多能用多少。多条策略会一起判断，任意一条达到上限就会拒绝本次请求。
```

## 说明卡片模式

### 系统处理流程

用 3 到 4 张小卡说明系统如何处理。每张卡包含标题和一句解释。

模板：

```text
先匹配对象
系统会根据租户、用户、API Key 等信息找出和当前请求有关的策略。

再匹配能力和模型
能力用于区分聊天、图片、视频等类型；模型留空表示全部模型适用。

任一超限就拒绝
同一个请求可能命中多条策略，只要其中一条达到上限，请求就会被拒绝。

状态控制生效
只有启用状态的策略参与判断；停用后保留配置但不生效。
```

### 术语解释

术语解释要短，不写百科。

模板：

```text
概率选择
分数越高越容易被选中，但不是每次都固定选同一条。这样既能偏向好路线，也能保留分流和容错空间。
```

### 风险提醒

提醒应具体，不要泛泛而谈。

示例：

```text
建议每次只调整 0.05 到 0.10，保存后观察调用日志、平均耗时、失败率和成本变化。
```

## 预设按钮模式

当用户需要同时配置多个字段时，应优先提供预设按钮。

预设按钮解决的问题：

- 用户不知道从什么数值开始。
- 多个字段之间存在比例或组合关系。
- 不同场景有典型配置。

每个预设必须包含：

1. 名称：表达使用目标。
2. 参数摘要：直接列出会填入的值。
3. 场景说明：说明适合谁或适合什么任务。

示例：

```text
成本优先
成本 0.55 / 速度 0.20 / 空闲 0.15 / 稳定 0.10
适合批量生成、离线任务、预算压力较大的业务。
```

交互要求：

- 点击预设后自动填入表单。
- 当前表单值完全匹配预设时，预设显示选中态。
- 套用预设后，用户仍可手动修改。
- 预设按钮不应该是普通小按钮；应做成卡片式按钮。

常见预设方向：

- 默认均衡：适合大多数用户。
- 成本优先：适合预算敏感场景。
- 体验优先：适合用户实时等待结果。
- 稳定优先：适合关键业务或高峰期。
- 轻量试用：适合新客户、测试环境。
- 高并发：适合明确评估过容量的业务。
- 只控某一项：适合用户只需要启用一个维度。

## 表单和弹窗布局

复杂弹窗建议宽度：

- 简单表单：520px 到 600px。
- 含预设按钮和多列数值：720px 到 820px。
- 字段非常多：考虑抽屉或页面内编辑，不要强塞小弹窗。

布局建议：

- 使用顶部标签，不用过窄左侧 label。
- 作用范围使用 2 列。
- 核心数值使用 2 到 3 列。
- 推荐预设使用 2 列卡片。
- 状态单独分区，并说明启用或停用的影响。

表单分区模板：

```text
作用范围
这条配置管谁、管哪类能力或模型。

推荐预设
点击后自动填入数值，再按业务容量微调。

核心参数
至少填写一项。留空表示这一项不限制。

策略状态
启用后参与后续请求判断；停用后保留配置但不生效。
```

## 视觉规范

整体风格：克制、清晰、适合后台工作台。

推荐视觉参数：

- 主卡片：白底、浅边框、12px 圆角。
- 内部卡片：白底或浅灰底、浅边框、8px 圆角。
- 栅格间距：12px 到 16px。
- 正文说明：12px 到 13px，行高约 1.6。
- 小标题：14px 到 15px，字重 700 到 800。
- 统计数字：20px 到 24px，字重 800 到 900。
- 标签：小色块或浅色标签，用于术语、状态、类别。

避免：

- 大面积渐变和装饰图形。
- 营销式 hero。
- 卡片套卡片过深。
- 所有内容都用同一种颜色。
- 预设按钮太小、文字挤在一行。
- 表格空值直接留空。

## 响应式要求

窄屏时：

- 4 列统计卡变 2 列或 1 列。
- 3 列表单变 1 到 2 列。
- 弹窗宽度不应导致横向滚动。
- 长文案必须允许换行。
- 按钮和输入框不能因为文案变长而挤压变形。

## 实施流程

AI 或开发者应按这个顺序改造页面：

1. 阅读现有页面和接口，找出核心对象、字段、动作。
2. 列出专业术语，逐个翻译成用户语言。
3. 写主卡片标题和副文案。
4. 写默认折叠说明区，解释系统处理流程和关键术语。
5. 设计当前状态反馈卡，帮助用户理解现有配置。
6. 识别是否需要预设按钮；如果多个字段要组合填写，就必须提供。
7. 优化主操作区标签、空值展示、状态展示。
8. 优化新增/编辑弹窗，按分区重排。
9. 检查交互反馈：保存、刷新、套用预设、启停状态。
10. 构建或运行测试，检查窄屏和长文案。

## 验收清单

页面完成后逐项检查：

- 用户第一眼知道页面是做什么的。
- 页面说明保存后影响什么、不影响什么。
- 专业术语被翻译成用户语言。
- 每个核心参数都有含义、影响和建议。
- 长说明靠近操作区且默认折叠。
- 多参数配置提供可点击预设。
- 预设能自动填值，并能显示当前选中态。
- 弹窗按业务任务分区，不是字段堆叠。
- 空值、停用、全部、无限制等状态都有明确文字。
- 保存、刷新、启停、套用预设有反馈。
- 样式与后台工具一致，清晰、克制、可扫描。
- 窄屏不挤压、不重叠、不横向溢出。
- 构建或测试通过。

## 给 AI 的通用提示词

在其他项目中可以直接复制下面提示词：

```text
请按“通用专业配置页体验优化指南”的风格优化这个后台配置页。

目标：
让普通用户能理解这个页面是做什么的、每个参数怎么用、调整后会有什么影响，并能从推荐预设开始安全配置。

要求：
1. 先阅读现有页面、接口和数据结构，保留现有业务行为，不改变后端契约。
2. 找出页面中的专业术语、缩写、内部字段名，把它们改成用户能理解的中文表达；必要时在说明里保留原缩写。
3. 主内容使用卡片式结构：标题、副文案、主要操作按钮、当前状态反馈、主操作区。
4. 在主卡片标题下面加入默认折叠的说明区，解释系统如何处理、关键术语、调大调小或留空的影响。
5. 如果页面需要同时配置多个相关参数，必须提供可点击的推荐预设。预设要包含名称、参数摘要、适用场景，点击后自动填入数值，并显示选中态。
6. 优化新增/编辑弹窗或抽屉，不要堆长表单。按“作用范围 / 推荐预设 / 核心参数 / 状态影响”等业务分区排版。
7. 表格列名、表单 label、空值展示、状态展示都使用用户语言，例如“不限制”、“全部模型”、“启用”、“停用”。
8. 视觉风格保持后台工作台风格：白底、浅边框、8-12px 圆角、12-16px 间距、清晰层级、克制颜色，不做营销页。
9. 检查响应式布局，保证窄屏下卡片、按钮、表单和表格不会文字重叠或严重挤压。
10. 完成后运行项目构建或测试，并说明验证结果。
```
