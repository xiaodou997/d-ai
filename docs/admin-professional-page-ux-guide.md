# 专业配置页体验优化指南

适用场景：后台里专业概念较多、用户不一定理解参数含义，但需要用户能安全完成配置的页面。参考页面：

- `admin/src/views/AIGateway/GatewayRouting.vue`
- `admin/src/views/AIGateway/GatewayLimits.vue`

目标不是把页面做成营销页，而是把专业配置页做成“看得懂、敢操作、知道影响”的工作台。

## 核心原则

1. 用普通用户能理解的词替代内部术语。
   例如把 `cost / latency / load / health` 表达为“成本优先 / 响应速度 / 繁忙程度 / 可用状态”。

2. 每个参数都要回答三个问题。
   “这是什么”、“调大或调小会怎样”、“什么场景建议这样用”。

3. 专业说明要靠近操作区，但不要压迫首屏。
   重要说明放在主卡片标题下方；内容较长时用折叠面板，默认折叠。

4. 给用户预设，而不是只给空表单。
   预设应该是一键套用的按钮，用户先选目标，再微调参数。

5. 保存前让用户看到当前配置是否合理。
   例如合计是否为 1.0、当前策略数量、启用状态、命中范围等。

## 推荐页面结构

专业配置页优先使用下面结构：

1. 主配置卡片
   - 标题：一句话说明这个页面管什么。
   - 副文案：说明保存后影响什么，不影响什么。
   - 操作按钮：刷新、新增、保存等放右侧。

2. 可折叠说明区
   - 放在主卡片标题下面。
   - 默认折叠，标题要能概括价值，例如“限流如何生效”。
   - 内容包含系统处理流程、术语解释、风险提醒。

3. 当前状态反馈
   - 用 3 到 4 个小统计卡展示当前配置状态。
   - 例如启用策略、停用策略、指定模型、对象类型。

4. 主操作区
   - 表单、滑块、表格或配置列表。
   - 标签使用业务语言，不直接暴露接口字段名。

5. 说明性辅助区
   - 只保留必要内容。
   - 和操作强相关的建议放进操作区，避免下面另起一组重复说明卡。

## 说明卡片写法

说明卡片要短、具体、可操作。推荐结构：

```text
先匹配对象
系统会根据租户、用户、API Key、Provider、Endpoint 找出和当前请求有关的策略。
```

不要写成：

```text
Scope 维度参与 runtime policy matching。
```

常用说明模块：

- “系统会怎么处理”：用 3 到 4 步解释流程。
- “容易误解的词”：把术语换成通俗解释。
- “调整会有什么影响”：说明调大、调小、留空、关闭的后果。
- “推荐怎么用”：给默认值或常见场景。

## 预设按钮设计

当页面有多个参数需要组合配置时，应提供预设按钮。

预设按钮内容建议包含：

- 名称：例如“默认均衡”、“成本优先”、“轻量试用”。
- 参数摘要：例如“成本 0.40 / 速度 0.30 / 空闲 0.20 / 稳定 0.10”。
- 适用场景：说明什么时候用。

交互要求：

- 点击后自动填入表单或权重。
- 当前配置刚好匹配某个预设时，该预设高亮。
- 用户套用后仍可继续微调。
- 预设按钮要足够大，不要挤成普通小按钮。

视觉建议：

- 使用 2 列或 4 列栅格，根据容器宽度自适应。
- 卡片圆角保持 8px 左右。
- 选中态用主色边框和浅色背景。
- 不要把过长文案塞进一行，允许换行。

## 弹窗表单设计

复杂配置弹窗不要只堆表单项。推荐分区：

1. 作用范围
   说明这条配置管谁、管哪类能力或模型。

2. 推荐预设
   放卡片式按钮，点击自动填值。

3. 配置数值
   把核心数字字段集中展示，必要时三列排布。

4. 状态
   单独说明启用、停用的影响。

弹窗宽度建议：

- 简单表单：560px 左右。
- 有预设、有多列数值、有说明文案：720px 到 800px。

表单标签建议使用顶部标签布局，减少左右挤压。

## 文案替换规则

优先使用用户语言：

| 内部词 | 页面表达 |
| --- | --- |
| Scope | 作用对象 |
| Scope ID | 对象 ID |
| RPM | 每分钟请求数 |
| TPM | 每分钟 Token |
| concurrency | 同时请求数 |
| latency | 响应速度 |
| load / inflight | 繁忙程度 |
| health / circuit breaker | 可用状态 / 保护期 |
| normalize | 按比例修正 / 归一化说明 |
| softmax | 概率选择 |
| sticky | 会话保持 |

保留缩写时要补充解释。例如可以写“每分钟请求数（RPM）”，但不要只写“RPM”。

## 样式规范

保持后台工具页的克制、清晰和可扫描：

- 主卡片：白底、浅边框、12px 圆角。
- 内部说明卡：8px 圆角、浅灰背景或白底浅边框。
- 小标签：深色文字或白字色块，用于强调术语。
- 栅格间距：12px 到 16px。
- 正文说明：12px 到 13px，行高 1.6 左右。
- 标题：14px 到 15px，字重 700 到 800。
- 不使用大面积渐变、装饰插画、营销式 hero。

## 实施检查清单

提交前逐项检查：

- 用户第一眼知道这个页面是做什么的。
- 每个专业参数都有通俗解释。
- 重要说明靠近操作区，长说明默认折叠。
- 有常用预设，且预设可点击自动应用。
- 预设高亮能反映当前配置。
- 弹窗分区清楚，不是长表单堆叠。
- 表格字段使用用户语言。
- 保存、新增、刷新等操作反馈明确。
- 移动端或窄屏不会出现文字严重挤压。
- `bun run build` 通过。

## 可复用提示词

后续遇到专业型配置页，可以直接使用：

```text
请按 docs/admin-professional-page-ux-guide.md 的风格优化这个后台配置页。
目标是让普通用户能理解页面是做什么的、每个参数怎么用、调整后会有什么影响。
要求：
1. 保留现有业务接口和主要行为，不改变后端契约。
2. 用通俗中文替换专业术语，必要时在说明中保留缩写。
3. 在主卡片标题下方增加默认折叠的说明区，解释系统如何处理和关键术语。
4. 对多参数配置提供可点击的推荐预设，点击后自动填入数值，并显示选中态。
5. 优化弹窗表单排版，按作用范围、推荐预设、核心参数、状态等分区。
6. 视觉风格参考 GatewayRouting.vue 和 GatewayLimits.vue：克制、清晰、卡片式、适合后台工具。
7. 完成后运行构建检查。
```
