# 回滚 SQL

`../changes/` 里的升级脚本是单向的。本目录存放与之配对的回滚脚本，
命名为 `NNNN_rollback.sql`，`NNNN` 是被回滚的那个升级脚本编号。

## 适用范围

回滚脚本**只**适用于「升级已执行、但业务流量尚未恢复」的维护窗口。
一旦放量，新产生的数据往往无法映射回旧结构，此时唯一正确的回滚是**恢复备份**。

因此每个回滚脚本都必须：

- 开头校验当前 schema 版本；
- 检测是否已有放量后产生的数据，有则直接 `RAISE EXCEPTION` 拒绝执行，
  而不是尽力而为地转换；
- 在单个事务内完成，并在最后把 `dai_schema_metadata.version` 改回来。

## 验证要求

回滚脚本发布前必须在真实数据上完成一次往返验证：

```text
旧基线 → 灌入含边界情况的数据 → 执行升级 → 执行回滚
```

并断言两点：

1. 业务关键数值（如各账户余额）与升级前**逐行完全一致**；
2. 列结构与旧基线 `init.sql` 完全一致。

未经往返验证的回滚脚本比没有回滚脚本更危险，不得发布。
